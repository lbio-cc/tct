# 接入指南

## 基本流程

1. 部署 `TCT`，记录 chain ID、合约地址和部署区块。
2. 业务平台调用 `registerPlatform`，从 `PlatformRegistered` 事件取得平台 ID。
3. 平台 owner 调用 `registerProject` 和 `createCredential`，保存链下业务标识与链上 ID 的映射。
4. 根据业务事实提交持有人变更、锁定/解锁及权益记录，等待交易确认。
5. 文件在链下保管，计算原始字节的摘要后调用 `registerFile`。
6. 组合 getter 与事件索引形成追溯页面，展示提交者、交易哈希、区块和业务说明。

写入接口返回的 ID 主要供合约内调用使用；普通客户端发送交易后应解析回执中的登记事件取得 ID，不应根据当前数量猜测下一个 ID。`scripts/demo.js` 提供完整示例。

## 元数据约定

建议元数据使用 JSON 字符串，描述性文字使用 `description`。以下是虚构示例，字段均为应用约定，并非合约强制规范：

```json
{
  "businessId": "DEMO-PROJECT-001",
  "description": "示例数据服务项目",
  "image": "https://example.com/project.png",
  "documents": [
    {
      "name": "示例说明文件",
      "hashAlgorithm": "sha256",
      "hash": "<原始文件字节的32字节摘要，提交前替换为实际值>",
      "url": "https://example.com/document.pdf"
    }
  ],
  "fields": [
    { "field": "businessId", "label": "业务编号" }
  ]
}
```

合约不校验 URL、摘要或 ID 关联。文件记录可在元数据中保存 `projectId`、`credentialId`，供应用索引；大整数 ID 推荐编码为十进制字符串。链下引用需同时绑定网络与合约实例。

更新元数据前，先读取并在链下合并完整 JSON，再序列化提交。空字符串保留原值，`{}` 会整体替换为一个空对象字符串。合约也接受不符合 JSON 格式的字符串，解析失败应由应用处理。

## 持有人、数量与状态

持有人字段为区分大小写的字符串，空格、大小写或不同编码会形成不同键。应用应在写入前统一标识格式，维护身份映射；合约不验证 DID、机构代码或身份声明。

数量均为整数，没有 decimals、货币或单位定义。应用应约定最小单位与精度，使用 ethers 6 的 `bigint` 处理链上整数，避免经由 JavaScript `Number` 丢失精度。持有人变更单次数量不得超出 `int256` 正数范围，并校验业务总量、余额、锁定及累计溢出边界。

状态值由应用定义，更新时需要显式传回希望保留的状态值；传入 0 也会写入。权益记录中的单位与结算凭据由链下系统定义和核验，合约不执行支付。

应用如有“锁定后禁止转出”要求，需在业务提交层实施；现有合约允许平台 owner 直接调用变更接口，不提供链上冻结约束。

## 文件摘要核验

`FileInfo.hash` 仅存储 `bytes32`，不包含算法字段。由应用在元数据中约定算法、编码与文件版本，对原始文件字节重新计算摘要，并与 `getFile` 返回值比较。

`scripts/demo.js` 使用 `keccak256` 演示；SHA-256 或其他输出 32 字节的算法也可由应用约定。合约不计算摘要、不下载文件，也不证明文件签章或文件中业务陈述的真实性。

`updateFile` 会替换当前非零摘要。要核验旧版本，应根据登记和更新事件定位当时摘要；历史文件原文与版本由应用保管。零摘要在更新接口中是“保留”的哨兵值，不是空字符串。

## 事件同步与历史查询

- 从部署区块起按区块、交易与日志顺序读取事件，按 RPC 限制分段抓取。
- 所有事件参数均未声明 `indexed`。可以按合约地址和事件签名筛选日志，按平台/项目/凭证 ID 的过滤需在索引服务解析后完成。
- 建议以 chain ID、合约地址、交易哈希、日志序号作为索引记录键，并处理链重组及重复抓取；不要把日志去重当作写入幂等。
- 平台项目、项目凭证及各类历史使用“长度 + 下标”读取，下标从 0 开始。越界会回滚。
- 持有人数量和历史长度查询没有统一的对象存在校验。不存在的凭证可能返回 0；确认存在性应调用 `getCredential`。
- 区块时间表示记录提交时间。业务发生时间如不同，可另存元数据，但该时间由提交方提供。
- 不同类型历史没有共同序号；统一时间线需借助交易和日志顺序。权益历史 getter 不含实际持有数量，需从 `CredentialBenefitRecorded` 事件取得。
- 项目、凭证和文件更新事件中的参数可能表示保留原字段。请按照 [设计说明](DESIGN.md) 的更新规则重放。

未提供平台文件列表接口，可从 `FileRegistered` 事件建立文件列表。当前也没有按持有人全局搜索、按摘要反查或业务编号查询接口，应由链下索引补齐。

## 开发验证

```bash
pnpm compile
pnpm test
pnpm demo
```

请先在本地链验证平台权限、更新保留规则、数量边界和查询流程，再按目标 EVM 链要求核对编译设置、操作码支持、Gas 与交易确认策略。本仓库没有预设公网网络或私钥配置。
