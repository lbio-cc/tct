# 数据模型与设计

## 定位

TCT 围绕业务对象组织链上记录，供应用追踪数字资产及业务数据的关键过程。当前实现采用平台、项目、凭证三层模型，事件类型限定为源码中的登记、更新、持有人变更、锁定/解锁和权益记录；没有任意事件图谱、自动追溯页面或可配置工作流引擎。

## 数据模型

| 对象 | 主要字段 | 关系与查询 |
| --- | --- | --- |
| Platform | `id / owner / name / metadata` | 内部维护项目 ID 与文件 ID 数组；公开接口仅提供项目枚举 |
| Project | `id / platformId / name / subject / status / metadata` | 属于一个平台，维护凭证 ID 数组 |
| Credential | `id / projectId / count / status / metadata` | 属于一个项目，关联持有人与业务历史 |
| HolderChange | `fromHolder / toHolder / count / metadata / timestamp` | 按凭证追加，时间为写入区块的 `block.timestamp` |
| HolderLock | `count / isLock / metadata / timestamp` | 按凭证与持有人追加 |
| Benefit | `holderCount / benefitCount / metadata / timestamp` | 按凭证与持有人追加 |
| FileInfo | `id / platformId / name / hash / metadata` | 属于一个平台，`hash` 为 `bytes32` |

各对象类别独立递增计数，首个 ID 为 1，同类别在本合约实例内全局递增。不同平台不会各自从 1 编号。跨网络或跨部署引用对象，应同时保存 chain ID、合约地址、对象类别及 ID。

`status` 没有内置枚举，也不控制写入权限或持有人变更。`metadata` 为普通字符串，JSON 结构、字段规范、文件关联均由应用约定。

## 权限

| 角色 | 可执行操作 |
| --- | --- |
| 任意地址 | 查询；登记新平台并成为该平台 owner |
| 平台 owner | 登记与更新所属项目、凭证、文件；记录持有人变更、锁定/解锁及权益；转移本平台 owner |
| admin | 转移 admin；转移任意平台 owner |

admin 不会绕过项目、凭证或文件接口的 owner 校验；若需要取得这些操作权限，需先转移平台 owner。转移后旧 owner 立即失去相应写入权限。

权限按所属平台向下继承，未提供操作员角色、持有人钱包授权或多签流程。持有人字符串本身不会授予调用权限。

## 数量语义

`createCredential` 与 `updateCredential` 的 `count` 是独立业务字段，创建凭证不会自动分配持有量。

`changeCredentialHolder` 要求 `count > 0` 且接收方非空：

1. `fromHolder` 为空时仅增加接收方数量，可表达初始分配或追加记账。
2. 来源非空时扣减来源数量并增加接收方数量，不校验来源余额、凭证总量、状态或锁定记录。
3. 来源和接收方可相同，净数量不变，但仍新增一条历史。
4. 接收方首次出现时加入持有人列表；数量归零后保留在列表中。仅作为来源出现的标识不会自动入列。

入参 `count` 是 `uint256`，计算时转换为 `int256`。接入方应将单次数量限制在 `1 .. 2^255-1` 并检查累计量范围，避免超大值转换改变符号；有符号加减溢出会回滚。此处保留原型记账行为，不能将其直接解释为受总量约束的资产余额。

锁定/解锁接口只追加记录，即使数量为 0、超过持有量或净解锁量超过锁定量也不会被业务规则拒绝。应用可按“锁定加、解锁减”计算净记录量，但合约不保证结果非负。

权益的 `holderCount` 是调用方提交的快照，不校验与当前数量一致。事件额外记录 `actualHolderCount`，而 `Benefit` 历史结构不保存该实际数量。`benefitCount` 不对应自动支付的金额。

## 更新与追溯

- `updateProject`：非空名称、主体、元数据覆盖原值；状态始终写入。
- `updateCredential`：数量和状态始终写入；元数据非空时覆盖。
- `updateFile`：名称与元数据非空时覆盖；摘要非全零时覆盖。全零摘要表示保留原值。

更新接口不合并 JSON，也不能通过空字符串清空原字段。需要保留某字段时应读取当前值，并按接口约定提交；并发写入可能覆盖前一笔更新，本实现没有版本号或幂等请求键。

更新事件记录的是调用参数，例如事件中的空名称或全零摘要可能表示“保留”，并非更新后的完整状态。还原历史需从登记事件开始按交易顺序应用更新规则。

持有人变更、锁定与权益历史只追加，未提供修改或删除接口。平台、项目、凭证、文件也未提供删除接口；其中可更新对象的 getter 只返回最新值。文件没有独立版本历史数组或按摘要反查接口，平台文件枚举也未公开，文件列表应索引登记事件。

## 链上与链下分工

合约负责写入者权限、对象归属、记录存储及事件。业务系统负责持有人身份映射、状态规则、总量核对、数量单位、幂等、文件保管、摘要计算与核验，以及按业务时间展示追溯路径。

查询公开可见，元数据和持有人标识不应直接存放未获授权公开的敏感原文。上链记录能追溯提交过程，业务真实性仍取决于数据来源及核验流程。
